## Mechanics (DECODED 2026-07-14 — frame-only solver `ring_paint.py`)

A basket navigates an 8-position RING (a 3x3 grid minus the centre) around a
**10x10 CANVAS**; a separate **10x10 TARGET** panel (top-left) shows the goal
pattern; **top swatches** select a colour; the level clears when the canvas
matches the target. Layout (measured): canvas at cols 27-36/rows 34-43 (starts
uniform), target top-left cols 3-12/rows 3-12, swatches in the top row (x>=20),
**100-move budget per level**.

**Paint-physics table (the reusable asset — each op overwrites its 10x10 region;
later ops paint over earlier):**

| Ring pos | ACTION5 launch region | ACTION6 arrow region (0/2/4/6 only) |
|---|---|---|
| 0 | top half (rows 0:5) | small top-centre patch (rows 0:3, cols 3:7) |
| 2 | right half (cols 5:10) | right-centre patch (rows 3:7, cols 7:10) |
| 4 | bottom half (rows 5:10) | bottom-centre patch (rows 7:10, cols 3:7) |
| 6 | left half (cols 0:5) | left-centre patch (rows 3:7, cols 0:3) |
| 1 | upper-right triangle (`[i, i:10]`) | — |
| 3 | lower-right triangle (`[i, 9-i:10]`) | — |
| 5 | lower-left triangle (`[i, 0:i+1]`) | — |
| 7 | upper-left triangle (`[i, 0:10-i]`) | — |

**⚠️ OFF-DIAGONAL WIN CHECK (load-bearing — will bite any future work):** the
game's win check compares canvas==target ONLY off the two main diagonals (the
anti-diagonal cells `[i,i]` and `[i,9-i]` are excluded). The planner must match
off-diagonal cells only, or it will over-search / never match.

**Solver**: `plan_paint` is a BFS over `(kind, ring_pos, colour)` ops (launches +
arrows) from the uniform canvas to the target (off-diagonal match); the WMA paint
phase navigates the ring (BFS) → selects a colour (swatch click) → launches
(ACTION5) or arrow-clicks (ACTION6 at `arrow_coords`) → settle-waits the
animation. Clears L1-L6 in ~108 actions. See [[../rounds/r53_unified-harness]]
"cd82 paint-solver round" (M1-M5) and [[../lessons/size_floor_and_settle_reads]].

## script25 adapter (R56, 2026-07-15) — `src/admorphiq/adapters25/cd82.py`

The kernel-composed quarantine adapter (stdlib + `admorphiq.kernels` +
`adapters25.base` only; `scripts/adapters25_lint.py` green) re-expresses the
ring-paint mechanic with ALL geometry measured from the frame — no hardcoded
pixel coordinates, palettes, or level solutions — and clears **6/6 in 97 actions,
game_score 0.98** (beats the legacy brittle 6/6 and the `ring_paint` 0.9463).

**Design: reactive replan-one-op.** Launch/arrow animations are ATOMIC to the
harness (the engine resolves the whole animation inside one `env.step` — the
ACTION5/arrow branches don't call `complete_action` until the paint finishes), so
every observation is a SETTLED frame. Each time its primitive queue empties, the
adapter re-reads the live canvas + target, BFS-plans the shortest launch/arrow op
sequence from the CURRENT canvas to the target (off-diagonal match, `_plan_paint`,
per-canvas dedup), and executes the FIRST op (navigate ring → select colour →
launch/arrow). Replanning from the actual canvas each op is self-correcting.

**Two porting bugs found + fixed (validate-first method):**
1. **Stale level-up frame.** The board redraws ONE FRAME AFTER `levels_completed`
   increments, so the transition frame still shows the PREVIOUS level's target;
   locking there froze wrong geometry and idled forever. Fix: gate the lock on a
   CLEAN uniform canvas region (present only pre-first-paint) AND two consecutive
   equal target reads. Same stale-frame family as [[SC25]]'s two-equal-reads lock.
2. **Arrow vs basket.** The arrow (`ctwspzkygu`, size ≤ ~14px) sits BEYOND the
   basket, whose border (≥30px) lies between it and the canvas; a min-distance
   pick grabbed the basket border. Fix: an arrow-max-size ceiling (`_ARROW_MAX_SIZE`)
   excludes the basket so the nearest small direction-aligned region IS the arrow.

**Frame-only geometry:** canvas = the uniform lower-half 10×10 (origin locked);
target = the upper-LEFT coloured block (its own colours ARE the paint palette,
which filters the swatch border colour out); swatches = top-band dots right of the
target whose colour is in the palette; arrow click = the small region just outside
the canvas on the basket's current side, detected at fire time. Composes
`kernels.find_regions`. Completes true **25/25 script25 adapter coverage**.
See [[../rounds/r56_generic-kernels]].

## Lessons Learned

- Current brittle solver works via hardcoded swatch positions; no v2 in API to test.
- R20 revealed that `_plan_navigation` was re-solving L1 on every obs
  call because the delegated `strat_bfs_state_space` internally does
  `reset(env)` and ignores `_ACTIVE_PREFIX`. The outer loop's prefix
  chaining from R15 didn't reach this plan path. R20+R22 rewrote
  `_plan_navigation` to call `BFSSolver.solve` directly with
  prefix awareness and an internal multi-level chaining loop.
- R20 direct probe: CD82 L1 cleared via `inferential_agent/navigation`
  (BFS with click_coords finds a 5-step solution). L2+ not reachable
  by frame-hash BFS because the paint-game mechanic (select swatch →
  navigate basket → fire launcher) has combinatorial depth beyond
  `max_states=15k`. A paint-specialist plan (swatch detection +
  target-pattern reading + executor identification) is required
  for L2+; out of scope for R20-R22.
