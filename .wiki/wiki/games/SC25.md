# SC25

> A TWO-PHASE spell game per level: click a 3×3 grid to toggle cells until the
> pattern EXACTLY matches an (auto-selected on L0–L2) target spell — which
> AUTO-CASTS — then walk the player into an exit. Both the R57 "T5/T6 vs T1"
> ambiguity and the wiki's old "click 3×3 slots" note are resolved by this:
> it is pattern-match THEN navigate (source-read + live-verified R56 2026-07-15).

## Mechanics (R56 2026-07-15 — source read + live verified)

`available_actions = [1,2,3,4,6]`. Each level:

1. **Pattern phase.** An interactive 3×3 grid of toggle cells (9 equal-size
   regions in a lattice at fixed pixel positions) + a target-pattern preview.
   ACTION6-clicking a cell flips it. When the grid EXACTLY matches the target
   spell's 3×3 pattern, the game **auto-casts** — no separate cast click.
   Levels 0–2 auto-select the spell; L3+ require clicking a spell sprite first.
2. **Navigate phase.** After the cast, move the player (ACTION1-4) into an
   exit cell to complete the level.

A per-level **click/action budget** (right-edge fill bar; L0=50, L1=25, …)
rises each action; overrun = GAME_OVER, resetting position + grid (not lives).
Gold solutions are short: L0 = 4 toggles + ~12 moves; L1 = 3 toggles + 2 moves.

### script25 adapter design (R56)

One frame-keyed BFS-from-start (the [[LS20]] planner), with the two phases
handled by a **per-key action restriction**: a PRE-cast key offers CLICKS
only (so the player never moves during the pattern phase → each pre-cast key
is a clean ≤512 toggle state, no position explosion), a POST-cast key offers
MOVES only. BFS-from-start then finds the single start→(clicks)→cast→(moves)→
exit path. State key = live-region signatures minus the left/right edge UI
strip (budget bar). Two measured subtleties: (a) **death-artifact discard** —
a budget-overrun move that resets to start is not recorded/tried, so a
fresh-budget life re-attempts it (without this, nav plateaus at 19 states);
(b) **cast detection** = a click redrawing >1 grid cell (the match redraws
3–4; a toggle exactly 1), off-grid preview changes ignored, suppressed on the
first (board-settle) action.

## Lessons Learned

- **2026-07-15 (R56) — the mechanic is pattern-match THEN navigate, not
  "click slots".** Reading the source settled the R57 ambiguity: the win check
  is `jsdgfdkecx` (exact 3×3 equality vs the target) → auto-cast → then walk
  the player sprite (`pluyoo`) into the exit. Frame-keyed BFS with a per-key
  click/move split clears L0 generically without decoding any of this.
- **BANKED WALL — L1+: near-match highlighting makes the frame-only cast
  signal ambiguous.** The game visually highlights NEAR-matches — a toggle
  bringing the grid within one cell of the target redraws multiple grid cells,
  structurally indistinguishable from the exact-match auto-cast by redraw-span
  alone. So the adapter commits to a non-winning near-match state and
  navigates from it (its 15 post-cast states are a closed region with no exit
  path; the real match + 2 moves would win). The signal is sufficient for L0
  (its match is the first multi-cell event reached) but not once near-matches
  highlight. **Reopen**: read the DISPLAYED target pattern (a colour-marked
  preview) to identify the exact required toggle state and click the differing
  cells — a perception step, not a search. L3+ also need spell-icon selection
  clicks (levels 0–2 auto-select). See the adapter module docstring.
- Frame-only (grid detected as an equal-cell lattice, cast structural) → the
  adapter transfers across version hashes, unlike the legacy `spell_cast`
  which reads `sptivk-*` sprite names. See [[../lessons/hardcoded_is_anti]].
