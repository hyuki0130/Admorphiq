## Mechanics Hypothesis

**Superseded (R56, gold-trace verified — see [[../lessons/ft09_glyph_decode_20260715]]).**
FT09 is NOT a coupled neighbourhood-toggle system: a click only ever
changes the clicked cell. The board is one or more 8-cell "rings" wrapped
around a 6x6 "glyph" occupying the ring's own center gap; the glyph is a
3x3 compass pattern painted in two ink colours that map to (a) the
glyph's own center marker colour and (b) the ring's other observed
button colour. A ring cell needs a click iff its current colour differs
from its glyph-predicted target. Some levels also have a two-phase
decoy -> reveal structure (see the lesson page). The original "lights-out
/ XOR-toggle with a coupled neighbourhood" hypothesis below is the
pre-R56 reading, kept for provenance.

Original (pre-R56) hypothesis: a lights-out / XOR-toggle puzzle where
each click modifies the clicked cell plus a neighborhood; the goal
configuration is encoded by constraint sprites. Solvable analytically via
linear algebra over the small finite field. This is the model
`_plan_lights_out`'s GF(2) stencil (R16-R18) still assumes, which is why
it stalls past L1 — see [[../lessons/gf2_lights_out_stencil_20260423]].

## Lessons Learned

- Current solver is brittle — v1 works, v2 fails. See the linked lessons for the underlying pattern and refactor path.
- Rounds R16-R18 added a GF(2) stencil + delta-chain solver to
  `_plan_lights_out` that clears L1 on v1 without sprite-tag reads
  (see `concepts/gf2_toggle_stencil`). L2+ unsolved: stencil density
  under top-diff cell selection is 91-100% on L2, meaning those
  cells are coupled display feedback, not buttons. The actual L2+
  buttons are elsewhere in the responsive list; additional
  constraint-indicator detection (non-toggling cells that encode
  the goal pattern) is needed for L2+ progression.
- **R56 (2026-07-15)**: gold-trace decode falsifies the coupled-neighbourhood
  reading entirely — see [[../lessons/ft09_glyph_decode_20260715]]. The new
  `adapters25/ft09.py` adapter decodes the glyph as primary strategy and
  falls back to the R16-R18 GF(2) stencil path (kept, not deleted) if the
  decode doesn't apply to a board it hasn't seen. Gold-trace verified
  byte-for-byte offline; live-env smoke run is the next open step.
