# AR25 — Mirror-Reflection Coverage Puzzle

> Movable colour glyphs are drawn together with their reflections across a movable mirror bar; a level is won when every goal cell is covered by some piece pixel or one of its reflections — NOT a single-avatar maze.

## Current Status

**2/8 depth, game_score 0.0833 @1000 (2026-07-16, deterministic ×2:
`scripts/rounds/ar25_geared_run`, `…_run2`).** Two frame-only learned-operator
paths, gated per level:

- **L0** — the R56 reflective-symmetry rebuild clears L0 in 23 actions at
  efficiency 1.0 (beats the 32-action human baseline → per-level cap) via
  `learn_reflection_operators` / `plan_reflection_coverage`. Byte-identical to
  the previous card (the geared path only runs when reflection is empty).
- **L1** — the geared-copy coverage path (2026-07-16, `learn_geared_operators`
  / `plan_geared_coverage`) clears L1, lifting game_score from 0.0278 (1/8) to
  **0.0833** (2/8). L1 is a coupled two-mode geared kaleidoscope (decode below);
  the adapter probes both ACTION5-toggled modes, learns each piece's per-control
  displacement, and plans a covering drive by a linear lattice solve. See "L1
  geared-copy CLEAR" below.

Both replace the earlier blind transition-graph explorer, which reached the
legacy `strat_bfs_state_space`'s 2/8 depth generically but only at absurd
budgets (L0 in ~835 actions, efficiency ≈ 0; 2/8 only at `giveup=30000`).
Blind search is BLIND to the reflection/geared coupling — the fix was to LEARN
it. Levels beyond L1 still fall back to graph exploration.

## Observations

### Frame-level (64×64, background colour 9)
- Several MOVABLE glyph pieces, each a distinct colour (level 0: a colour-5
  shape and a colour-4 shape).
- One or more thin full-length MIRROR BARS (level 0: a colour-10 vertical
  band spanning the height).
- A GOAL glyph: a cluster of same-coloured target cells that must all be
  covered (level 0: 45 colour-11 cells).
- Two edge-pinned HUD bands: a bottom-row STEP COUNTER that shrinks one cell
  per action, and a right-column progress bar. Both must be masked before
  hashing the board (they otherwise make every action look like a new state).
- A small marker (colour-0 pixels) rides the currently ACTIVE piece.

### Action effects
- `ACTION1..4` move the ACTIVE piece one cell (some pieces are
  axis-constrained). Because the piece is rendered with all its mirror
  reflections, one press changes MANY pixels at once (~109 on level 0), not
  the ~1-cell diff of a single-avatar step.
- `ACTION5` cycles which piece is active; `ACTION6` selects a piece by click;
  `ACTION7` undoes the last move (a real reversible back-edge).
- The mirror bar is itself movable on some levels, changing where reflections
  land.

## Mechanics Hypothesis

- Coverage puzzle over a kaleidoscope: arrange the pieces (and, via the mirror
  bar, their reflections) so the whole goal glyph is covered simultaneously.
- The effective state is the joint configuration of every piece + the mirror
  bar + which piece is active — coupled by the reflection rule. This is a
  [[../concepts/merge_mechanic]]-adjacent coverage condition, NOT a navigation
  goal, so plain shortest-path over a single cluster does not apply.

## Solution Pattern (frame-only — learned reflection model)

Compose the reflective-symmetry motion kernels (`learn_reflection_operators` /
`plan_reflection_coverage`, the mirror analogue of `learn_point_operators` /
`plan_overwrites`):

1. **Probe** each of ACTION1-4 once, each immediately followed by ACTION7
   (UNDO), so every measured transition starts from the identical level-start
   board. One move translates the piece AND every reflected image at once.
2. **Learn** the model from those before/after pairs: a COLUMN move splits the
   piece from its image by opposite column shift (image column moves the other
   way), which recovers the vertical mirror axis (doubled position `k`, so
   `c -> k-c`); the driven piece's colours + full colour-membership footprint;
   and the per-action pixel displacement. (Reflections render in a DISTINCT
   colour, so a colour-membership footprint never picks up the image — this is
   why the footprint is exact where `track_objects`' matched subset dropped
   marker cells.)
3. **Detect the goal** as the largest static (non-moving-colour) cluster after
   HUD masking.
4. **Plan** with `plan_reflection_coverage`: BFS over piece translations for
   one whose rendered footprint (piece + reflections) covers the goal — the
   game's own WIN fires as soon as coverage is achieved.

Fallback: no axis split (off-screen mirror, axis-constrained piece, multi-piece
joint level) ⇒ the same generic transition-graph frontier explorer the previous
build used, so depth never regresses below that baseline.

### L1 axis-from-correspondence probe (2026-07-15) — BANKED, structure diverges

The proposed L1 lever was "derive the mirror axis from the piece↔image
CORRESPONDENCE geometry (perpendicular-bisector midline of matched pairs) instead
of needing the mirror bar visible." A validate-first live probe (drive to L1,
issue ACTION1-4 each with an ACTION7 undo, dump the shift groups; script
`scratchpad/ar25_l1probe.py`) shows the lever does NOT apply — L1 is a
different STRUCTURE, exactly the STOP-RULE "multiple mirrors / recursive depth"
case:

- L1 board (64×64, bg 9): two 40-cell blobs (colours 4 and 5) + ten singletons
  (colours 0, 11). Images render — the premise that "nothing renders" is false.
- **ACTION3** moves two groups by `(0,-3)` (21 cells) and `(0,-6)` (72 cells);
  **ACTION4** by `(0,+3)` and `(0,+6)`. Both groups move in the SAME direction,
  at 1× and 2× the displacement. A single mirror produces OPPOSITE motion
  (piece `-3` ⇒ image `+3`); 2× SAME-direction motion is a DOUBLE reflection —
  i.e. two (parallel) mirrors. No opposite-shift pair exists under any probe.
- `learn_reflection_operators` therefore returns `axes=[]`, `piece_cells=0`,
  `delta_map={}` — correct, not a bug.

Why the correspondence fix cannot rescue it: the perpendicular-bisector midline
recovers a SINGLE reflection axis from a piece and its MIRROR image (opposite
motion). At L1 the co-moving groups are TRANSLATES of the piece (same-direction,
multiples), the signature of parallel mirrors generating a translation subgroup —
not a reflection pair, so their bisector is not a mirror axis and reflecting the
piece across it does not reproduce the image (the IoU check would fail). Modelling
L1 needs a MULTI-mirror reflection group (image at `k·δ` for reflection count `k`),
a distinct and larger kernel than the single-axis model — out of a one-pass scope.
Banked with the probe data; no code change (the floor is byte-identical). The real
reopen pointer is a multi-mirror / reflection-group coverage model, not a
correspondence tweak.

### L1 double-reflection re-verification (2026-07-16) — CONFIRMED + representability sharpened

A second validate-first live probe (drive to L1 with the REAL adapter — L0
clears in 23 actions — then issue horizontal moves FIRST from the pristine L1
start, each with an ACTION7 undo; script `scratchpad/ar25_l1probe.py`) reproduced
the 2026-07-15 reading EXACTLY and across BOTH probe orderings, and settled the
"is a two-mirror composition representable?" question with a proof:

- **Floor unchanged (deterministic ×2):** ar25 = 1/8 @ **0.0278** @1000 on env
  `ar25-0c556536` (`scripts/rounds/ar25_l1_floor_a`, `…_floor_b`). No code change,
  so L0 is byte-identical.
- **Same-direction integer-multiple co-motion reproduced:** on the SETTLED L1
  board the color-0 group (21 cells) shifts `±3` and the color-4 group (72 cells)
  shifts `±6` — exactly **2×, same direction** (ACTION3 → `(0,-3)`/`(0,-6)`,
  ACTION4 → `(0,+3)`/`(0,+6)`). No opposite-shift pair under any probe, so
  `learn_reflection_operators` returns `axes=[]`, `piece_cells=0`, `delta_map={}`
  and the adapter falls back to graph — confirmed correct, not a bug.
- **New detail — a staging→play-field relocation on first input.** The L1 START
  frame renders the two 40-cell blobs (colours 5, 4) in a staging strip at rows
  45-53; the FIRST move from L1-start (any action) relocates them −24 rows into
  the play field (colours swap horizontal sides), a large re-layout whose undo
  does not cleanly restore (~292 cells). The clean 1×/2× signal is a property of
  the post-relocation board and is stable there.

**Representability proof — a two-axis composition of the EXISTING reflection
kernel CANNOT model L1 (correcting the "just apply reflect twice" reading).**
Any arrangement of STATIC mirror lines maps the piece to images by a composition
of reflections: an even count composes to a pure translation, an odd count to a
glide-reflection. Under a piece translation by `(0, δc)` every such image moves by
exactly `±1·δc` (the even-count images `+δc`, the odd-count images `−δc`) — NEVER
`2·δc`. So the observed 72-cell group moving at `+2·δc` is impossible under ANY
number of static mirrors, and `reflection_orbit`'s multi-axis closure (which is
exactly that static-mirror group) would predict `1×` motion and fail coverage.
The `k·δ` image therefore is NOT a reflection-group artifact at all: it requires
a MOVING mirror (mirror translating with the piece, so
`image = 2(m+δ_m) − (c+δc)` can reach `2δc`) or a geared/lattice multi-copy
system. Modelling L1 needs BOTH a new **learner** (key on same-direction
integer-multiple co-motion, not opposite-shift reflection pairs) AND a new
**dynamics/render** model (image at `k·δ`), i.e. a distinct kernel — beyond one
bounded pass. STOP-RULE hit: banked docs-only, floor byte-identical. The reopen
pointer is a moving-mirror / geared-copy `k·δ` dynamics model, not a multi-axis
extension of the current static-reflection kernel.

### L1 geared-copy full decode (2026-07-16) — dynamics EXACTLY learnable, but win is a JOINT coupled search — BANKED

A dedicated geared-copy round decoded L1's controls completely (scripts
`scratchpad/ar25_l1decode.py`, `…_l1switch.py`; drive to L1, relocate with one
move, then probe every action in each control mode with inverse-move restores).
The verdict: the `k·δ` geared **learner** the reopen pointer called for is real
and works PERFECTLY, but L1's WIN is a coupled multi-piece, two-mode, dual-goal
coverage search — beyond "drive images onto a target" and beyond one pass.

**Floor unchanged (deterministic ×2 + a post-round confirm):** ar25 = 1/8 @
**0.0278** @1000 on env `ar25-0c556536` (`scripts/rounds/ar25_l1_floor_a`,
`…_floor_b`, `…ar25_geared_floor`). No code change → L0 byte-identical.

**The geared linear model is EXACTLY learnable (IoU = 1.000).** On the settled
(post-relocation) board a horizontal press moves color-0 (21 cells) by `±3` and
color-4 (72 cells) by `±6`. Modelling each moving group's footprint (by colour
membership in the reference frame) as translating linearly by `net_presses ×
per-press-shift` predicts the ACTUAL next board's moving foreground at **IoU
1.000** (93/93 cells). Opposite moves are exact inverses (ACTION3∘ACTION4 → diff
0), so the post-relocation system is a clean reversible lattice. **The learner
concept is validated — this is NOT why the round banks.**

**Why it banks — L1 is a coupled, two-mode, dual-goal geared coverage puzzle:**

- **ACTION5 toggles between two control modes** (states alternate p0/p2/p4 ≡ mode
  A, p1/p3 ≡ mode B; the ~29-cell diff on toggle is just the active-marker):
  - **Mode A** — horizontal press: color-4 (72) at **2×**, color-0 (21) at **1×**;
    vertical (ACTION1/2) INERT.
  - **Mode B** — vertical press: a 140-cell group (colours 0,4,5) at **1×** plus a
    color-0 singleton at **4×**; horizontal press: color-4 (72) at 1×, a color-0+5
    group (66) at 1×, and a color-0 pair at **3×**.
  So gear ratios of **1×, 2×, 3×, 4×** all appear, and a SINGLE press moves
  SEVERAL pieces at once at their own fixed ratios (they cannot be moved
  independently).
- **Two static goal glyphs** must be covered simultaneously: color-11 (72 cells,
  bbox `(42,3,53,17)`, lower-left) and color-5 (64 cells, bbox `(18,45,29,59)`,
  upper-right).
- **No single-mode drive can cover a goal.** An exhaustive net-horizontal search
  in mode A finds NO drive whose union footprint covers color-11 (rows differ and
  the coupling constrains column alignment), and a raw horizontal sweep never
  clears. Covering both goals requires coordinating horizontal (mode A) + vertical
  (mode B) drives across mode toggles, under the shared-control gear coupling — a
  joint coupled-lattice configuration search, not a 1-D or single-piece drive.

**Reopen pointer (precise).** A JOINT geared-coverage kernel: state = the net
`(mode-A-horizontal, mode-B-horizontal, mode-B-vertical)` press counts; each piece
renders at `start + Σ (press_count × its per-mode-per-press shift)`; goal = both
static glyphs ⊆ the union of all pieces' rendered footprints; BFS/A* over the
coupled press-count lattice (`configuration_path`). This is a distinct, larger
build than the single-piece `plan_reflection_coverage`/`plan_geared_coverage`
shape and needs the two-mode control model first — out of one bounded pass. A
single-piece geared kernel was deliberately NOT shipped: it is provably inert on
L1 (would add dead code + risk the byte-identical L0 guarantee for zero score).
The decoded dynamics above are the exact spec for that kernel when it is scoped.

### L1 geared-copy CLEAR (2026-07-16) — 1/8 → 2/8 @ 0.0833

The geared kernel scoped above was BUILT and L1 is CLEARED — game_score
**0.0278 → 0.0833** (2/8), deterministic ×2 (`scripts/rounds/ar25_geared_run`,
`…_run2`, @1000 on `ar25-0c556536`). The "joint coupled search" fear was
resolved by a correction and a linear solve:

- **There is only ONE static goal, not two.** The earlier decode called
  color-5 (64 cells, upper-right) a second goal; the two-mode probe shows it is
  a MOVING PIECE (it translates in mode B). By POSITION, the only never-moving
  cluster ≥ 20 cells is color-11 (72 cells) — the single goal, matching L0's
  color-11 goal.
- **The covering piece + offset are computed, not searched.** color-4 (the
  72-cell moving piece) covers color-11 by the single translation **(24, −18)**,
  and that offset is lattice-reachable (row step 3 via mode-B B2, col step 3 via
  mode-A A3): `24 = 8·(+3 down)`, `−18 = 3·(−6 left)`. The geared dynamics are
  LINEAR, so coverage reduces to (a) find the offset aligning a piece onto the
  goal and (b) decompose it into per-control press counts — no deep search. The
  first BFS attempt returned None only because BFS over the 8-control lattice is
  ~4-5 presses deep while the solution is 11 presses; `plan_geared_coverage`'s
  **tier-1 lattice solve** finds it directly.
- **Live-verified plan**: mode-A A3×3 (−18 cols) + ACTION5 toggle + mode-B B2×8
  (+24 rows) drives color-4 onto color-11; `levels_completed` goes 1→2 on the
  8th B2 press (`scratchpad/ar25_l1exec.py`).

**How the adapter path works** (gated so L0 is byte-identical — the geared path
runs ONLY when `learn_reflection_operators` returns empty axes, which L0 never
does): on reflection-failure the adapter enters a `geared_probe` phase that
probes ACTION1-4 in each of the two ACTION5-toggled modes (each move restored by
its opposite), runs `learn_geared_operators` to recover every piece's
per-control displacement, detects the goal as the largest static-by-position
cluster, plans the covering drive with `plan_geared_coverage`, and executes it
(mode-A controls, one toggle, mode-B controls). Falls back to graph if no
covering plan exists.

**Kernels** (generic, no game constants; `src/admorphiq/kernels/motion.py`,
unit-tested in `tests/test_kernels_motion.py`): `learn_geared_operators`
partitions co-moving cells into pieces by their shift-signature across labelled
controls and returns each piece's per-control displacement; `render_geared`
applies the linear geared dynamics; `plan_geared_coverage` does the two-tier
(lattice-solve then BFS-fallback) covering-count search. This is the
complementary regime to `learn_reflection_operators`: geared keys on
same-direction integer-multiple co-motion (no opposite-shift pair), which is
exactly why the reflection learner stays empty on it (pinned by a contrast
test).

### L2 probe (2026-07-16) — same geared FAMILY, harder mechanic — BANKED, lane closes at 2/8

A bounded L2 probe (drive the real adapter through L0+L1 to L2 in 60 actions,
then characterize; `scratchpad/ar25_l2decode.py`) shows L2 is the SAME geared
family (first-move relocation of 613 cells; ACTION5-toggled control modes;
pieces translate at integer multiples) but a qualitatively HARDER instance that
the current kernel + adapter do NOT clear as-is or by trivial generalization.
Three measured escalations:

- **Diagonal (non-axis-aligned) controls, base_step 1.** L1's controls each
  moved a piece along ONE axis (row-only or col-only). At L2 a single control
  moves a piece 2D-diagonally — e.g. a colour-10 piece (88 cells) shifts
  `(−3, +9)` under A1 and `(+3, 0)` under A2; another colour-10 piece (72)
  shifts `(−3, 0)` / `(+3, +4)`. `_decompose_offset` only decomposes
  axis-aligned controls, so it returns None for these and the planner falls to
  the shallow BFS tier (no plan). A general lattice-basis solve over
  non-axis-aligned integer shift vectors would be needed.
- **FIVE simultaneous static goals** (by position, ≥ 20 cells): colour-11 × 4
  (sizes 63/54/54/63) + colour-5 × 1 (56). L1 had ONE goal, solved by a single
  count-vector; five independent goals is a true joint multi-target coverage
  the tier-1 single-count-vector solve does not attempt.
- **No single piece translate-covers any goal.** The big moving pieces are
  colour-10 (88, 72); every goal is colour-11 or colour-5; `covering_offsets`
  returns 0 for every (big-piece, goal) pair. So the covering STRUCTURE is
  itself undecoded — coverage must come from piece UNIONS or a different win
  condition, not one piece onto one goal. (colour-5 is again both a moving
  piece (48) and a static goal (56), and there is no colour-11 moving piece at
  all.)

Together these make L2 a distinct, larger build — a diagonal/general-lattice
decomposer AND a real multi-target joint search AND more decode of the covering
structure — well beyond one bounded pass. Banked docs-only; no code change, so
the card stays **2/8 @ 0.0833** byte-identical. The ar25 lane closes for the
sprint at 2/8 (L0 super-human reflection + L1 geared). Reopen pointer: decode
L2's covering structure (which piece-union covers which goal), then generalise
`plan_geared_coverage` to non-axis-aligned shift lattices + independent
multi-target coverage.

## Lessons Learned

- **The piece footprint is the co-moving cell set, not one colour.** The piece
  (colour 5) carries marker pixels (colour 0) that translate with it and are
  part of what the game reflects — the reflected image is the FULL 45-cell
  footprint, so planning with only the 40 colour-5 cells (or `track_objects`'
  42-cell matched subset) fails to cover the 45-cell goal. Footprint = every
  cell of the driven colours in the reference frame.
- **`base.available_action_ids` only surfaces ids 1-5.** ACTION7 (undo) must be
  read from the raw `available_actions` — the previous adapter listed 7 but
  never actually issued it (a latent no-op).
- The old "player navigates around walls to a goal cell" model on this page
  was FALSIFIED by reading the game source and a live probe: AR25 is a
  mirror-reflection coverage puzzle. A game passing generic BFS on shallow
  levels does not confirm the assumed mechanic — depth exposes it.
