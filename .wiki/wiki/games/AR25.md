# AR25 — Mirror-Reflection Coverage Puzzle

> Movable colour glyphs are drawn together with their reflections across a movable mirror bar; a level is won when every goal cell is covered by some piece pixel or one of its reflections — NOT a single-avatar maze.

## Current Status

The R56 reflective-symmetry rebuild (`script25` quarantined adapter) now
**clears L0 in 23 actions with efficiency score 1.0** (beats the 32-action
human baseline → per-level cap), lifting game_score from **4.1e-05 → 0.0278**
(2026-07-15, `scripts/rounds/script25_ar25_reflectN`). game_score 0.0278 is
the completion cap for clearing only L0 of 8 (weight 1 of Σ1..8 = 36), so the
lever from here is DEPTH, not L0 efficiency (already maxed).

This replaces the earlier blind transition-graph explorer, which reached the
legacy `strat_bfs_state_space`'s 2/8 depth generically but only at absurd
budgets (L0 in ~835 actions, efficiency ≈ 0; 2/8 only at `giveup=30000`).
Blind search is BLIND to the reflection coupling — the fix was to LEARN it.

Deeper levels (L1+) still fall back to graph exploration. The reason was
CORRECTED by a live probe (2026-07-15, see "L1 axis-from-correspondence probe"
below): it is NOT that the L1 mirror renders off-screen — the images DO render
and move. L1 has MULTIPLE (parallel/recursive) mirrors, so a move translates the
images in the SAME direction at INTEGER MULTIPLES of the piece displacement, not
in the opposite direction a single mirror produces. There is no opposite-shift
axis split to learn, so `learn_reflection_operators` correctly returns empty and
the adapter falls back to graph. The adapter is 1/8 at standard budgets, L0
efficient.

## Observations

### Frame-level (64×64, background colour 9)
- Several MOVABLE glyph pieces, each a distinct colour (level 0: a colour-5
  shape and a colour-4 shape).
- One or more thin full-length MIRROR BARS (level 0: a colour-10 vertical
  band spanning the height).
- A GOAL glyph: a cluster of same-coloured target cells that must all be
  covered (level 0: 45 colour-11 cells).
- Two edge-pinned HUD bands: a bottom-row STEP COUNTER that shrinks one cell
  per action, and a right-column progress bar. Both must be masked before
  hashing the board (they otherwise make every action look like a new state).
- A small marker (colour-0 pixels) rides the currently ACTIVE piece.

### Action effects
- `ACTION1..4` move the ACTIVE piece one cell (some pieces are
  axis-constrained). Because the piece is rendered with all its mirror
  reflections, one press changes MANY pixels at once (~109 on level 0), not
  the ~1-cell diff of a single-avatar step.
- `ACTION5` cycles which piece is active; `ACTION6` selects a piece by click;
  `ACTION7` undoes the last move (a real reversible back-edge).
- The mirror bar is itself movable on some levels, changing where reflections
  land.

## Mechanics Hypothesis

- Coverage puzzle over a kaleidoscope: arrange the pieces (and, via the mirror
  bar, their reflections) so the whole goal glyph is covered simultaneously.
- The effective state is the joint configuration of every piece + the mirror
  bar + which piece is active — coupled by the reflection rule. This is a
  [[../concepts/merge_mechanic]]-adjacent coverage condition, NOT a navigation
  goal, so plain shortest-path over a single cluster does not apply.

## Solution Pattern (frame-only — learned reflection model)

Compose the reflective-symmetry motion kernels (`learn_reflection_operators` /
`plan_reflection_coverage`, the mirror analogue of `learn_point_operators` /
`plan_overwrites`):

1. **Probe** each of ACTION1-4 once, each immediately followed by ACTION7
   (UNDO), so every measured transition starts from the identical level-start
   board. One move translates the piece AND every reflected image at once.
2. **Learn** the model from those before/after pairs: a COLUMN move splits the
   piece from its image by opposite column shift (image column moves the other
   way), which recovers the vertical mirror axis (doubled position `k`, so
   `c -> k-c`); the driven piece's colours + full colour-membership footprint;
   and the per-action pixel displacement. (Reflections render in a DISTINCT
   colour, so a colour-membership footprint never picks up the image — this is
   why the footprint is exact where `track_objects`' matched subset dropped
   marker cells.)
3. **Detect the goal** as the largest static (non-moving-colour) cluster after
   HUD masking.
4. **Plan** with `plan_reflection_coverage`: BFS over piece translations for
   one whose rendered footprint (piece + reflections) covers the goal — the
   game's own WIN fires as soon as coverage is achieved.

Fallback: no axis split (off-screen mirror, axis-constrained piece, multi-piece
joint level) ⇒ the same generic transition-graph frontier explorer the previous
build used, so depth never regresses below that baseline.

### L1 axis-from-correspondence probe (2026-07-15) — BANKED, structure diverges

The proposed L1 lever was "derive the mirror axis from the piece↔image
CORRESPONDENCE geometry (perpendicular-bisector midline of matched pairs) instead
of needing the mirror bar visible." A validate-first live probe (drive to L1,
issue ACTION1-4 each with an ACTION7 undo, dump the shift groups; script
`scratchpad/ar25_l1probe.py`) shows the lever does NOT apply — L1 is a
different STRUCTURE, exactly the STOP-RULE "multiple mirrors / recursive depth"
case:

- L1 board (64×64, bg 9): two 40-cell blobs (colours 4 and 5) + ten singletons
  (colours 0, 11). Images render — the premise that "nothing renders" is false.
- **ACTION3** moves two groups by `(0,-3)` (21 cells) and `(0,-6)` (72 cells);
  **ACTION4** by `(0,+3)` and `(0,+6)`. Both groups move in the SAME direction,
  at 1× and 2× the displacement. A single mirror produces OPPOSITE motion
  (piece `-3` ⇒ image `+3`); 2× SAME-direction motion is a DOUBLE reflection —
  i.e. two (parallel) mirrors. No opposite-shift pair exists under any probe.
- `learn_reflection_operators` therefore returns `axes=[]`, `piece_cells=0`,
  `delta_map={}` — correct, not a bug.

Why the correspondence fix cannot rescue it: the perpendicular-bisector midline
recovers a SINGLE reflection axis from a piece and its MIRROR image (opposite
motion). At L1 the co-moving groups are TRANSLATES of the piece (same-direction,
multiples), the signature of parallel mirrors generating a translation subgroup —
not a reflection pair, so their bisector is not a mirror axis and reflecting the
piece across it does not reproduce the image (the IoU check would fail). Modelling
L1 needs a MULTI-mirror reflection group (image at `k·δ` for reflection count `k`),
a distinct and larger kernel than the single-axis model — out of a one-pass scope.
Banked with the probe data; no code change (the floor is byte-identical). The real
reopen pointer is a multi-mirror / reflection-group coverage model, not a
correspondence tweak.

## Lessons Learned

- **The piece footprint is the co-moving cell set, not one colour.** The piece
  (colour 5) carries marker pixels (colour 0) that translate with it and are
  part of what the game reflects — the reflected image is the FULL 45-cell
  footprint, so planning with only the 40 colour-5 cells (or `track_objects`'
  42-cell matched subset) fails to cover the 45-cell goal. Footprint = every
  cell of the driven colours in the reference frame.
- **`base.available_action_ids` only surfaces ids 1-5.** ACTION7 (undo) must be
  read from the raw `available_actions` — the previous adapter listed 7 but
  never actually issued it (a latent no-op).
- The old "player navigates around walls to a goal cell" model on this page
  was FALSIFIED by reading the game source and a live probe: AR25 is a
  mirror-reflection coverage puzzle. A game passing generic BFS on shallow
  levels does not confirm the assumed mechanic — depth exposes it.
