# AR25 — Mirror-Reflection Coverage Puzzle

> Movable colour glyphs are drawn together with their reflections across a movable mirror bar; a level is won when every goal cell is covered by some piece pixel or one of its reflections — NOT a single-avatar maze.

## Current Status

Legacy `strat_bfs_state_space` cleared 2/8 on both v1 and v2 at a ~500K
state-expansion budget (efficiency ≈ 0). The R56 namespace-safe re-build
(`script25` quarantined adapter, generic transition-graph explorer) reaches
the **same 2/8 depth generically** — 1/8 at the 1000/3000-action smokes
(L0 in ~835 actions vs a 32-action human baseline), and 2/8 at a longer
exploratory `giveup=30000` run (L1/level-2 in 14791 actions vs 50 human).
It is **BANKED on efficiency**: coverage matches the legacy solver, but blind
search scores ≈ 0 on the squared-efficiency metric. The wall is
combinatorial, not a wiring gap — see Lessons.

## Observations

### Frame-level (64×64, background colour 9)
- Several MOVABLE glyph pieces, each a distinct colour (level 0: a colour-5
  shape and a colour-4 shape).
- One or more thin full-length MIRROR BARS (level 0: a colour-10 vertical
  band spanning the height).
- A GOAL glyph: a cluster of same-coloured target cells that must all be
  covered (level 0: 45 colour-11 cells).
- Two edge-pinned HUD bands: a bottom-row STEP COUNTER that shrinks one cell
  per action, and a right-column progress bar. Both must be masked before
  hashing the board (they otherwise make every action look like a new state).
- A small marker (colour-0 pixels) rides the currently ACTIVE piece.

### Action effects
- `ACTION1..4` move the ACTIVE piece one cell (some pieces are
  axis-constrained). Because the piece is rendered with all its mirror
  reflections, one press changes MANY pixels at once (~109 on level 0), not
  the ~1-cell diff of a single-avatar step.
- `ACTION5` cycles which piece is active; `ACTION6` selects a piece by click;
  `ACTION7` undoes the last move (a real reversible back-edge).
- The mirror bar is itself movable on some levels, changing where reflections
  land.

## Mechanics Hypothesis

- Coverage puzzle over a kaleidoscope: arrange the pieces (and, via the mirror
  bar, their reflections) so the whole goal glyph is covered simultaneously.
- The effective state is the joint configuration of every piece + the mirror
  bar + which piece is active — coupled by the reflection rule. This is a
  [[../concepts/merge_mechanic]]-adjacent coverage condition, NOT a navigation
  goal, so plain shortest-path over a single cluster does not apply.

## Solution Pattern (frame-only, partial)

Treat the board as a generic state-space search re-expressed through
namespace-safe kernels (the wiki's original "bfs_state_space" template, made
namespace-safe):
1. Mask the edge-pinned HUD bands (step counter, progress bar) via
   [[../concepts/frame_hashing]]-style region detection, then canonicalise the
   masked board into a stable state key.
2. Record every observed `(state, action, next_state)` transition; UNDO gives
   cheap back-edges.
3. Explore systematically: untried action from the current state first, else
   route over the recorded transitions to the nearest state with an untried
   action.

**Why it only partially generalizes**: the search is BLIND to the reflection
coupling, so the reachable-state count explodes before the coverage-WIN
configuration is stumbled upon. It clears the shallow level 0 and stalls. The
real lever is LEARNED reflective dynamics (infer the mirror axis + the
piece→reflected-image map from before/after frames) feeding a
configuration-space plan — not more blind search.

## Notes / Refactor Plan

- The legacy 2/8 depended on a ~500K-expansion budget three orders of
  magnitude beyond a normal run and still scored ≈ 0 on the squared-efficiency
  metric — coverage count, not efficiency.
- Reopen pointer: a generic `learn_reflection_operators` motion kernel (same
  shape as the existing `learn_point_operators` / `plan_overwrites` pair,
  generalised to reflective symmetry) would let a configuration-space planner
  target coverage in a learned model. Until it exists, AR25 stays banked at
  the shallow-clear plateau.
