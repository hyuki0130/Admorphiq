# SK48 — Snake Shape / Pattern-Matching Puzzle

> Move a snake so the sequence of coloured cells its body overlaps matches a per-level TEMPLATE pattern, within a fixed move budget — NOT a plain eat-food snake or a reach-exit maze.

## Current Status

- Agent regression: **0/8** on both v1 and v2 (a legacy `sk48_snake`
  strategy once cleared 1/8; it was budget-fragile — see Lessons).
- R56 namespace-safe transition-graph explorer: **0/8** at the 1000-action
  smoke (game_score 0.0). **BANKED** — the shape-matching win is a
  combinatorial body-configuration target that blind frontier search does
  not construct at the smoke budget (unlike AR25/SP80/R11L, where a generic
  explorer at least ties the legacy shallow level).

## Observations

- `available_actions = [1, 2, 3, 4, 6, 7]` (v2 board, background colour 5).
- The board is split by a full-width divider (colour 2, row ~53) into a TOP
  arena — the controllable snake (a colour-6 head) plus a row of coloured
  TARGET cells (colours 8, 9, 14) — and a BOTTOM TEMPLATE showing the goal
  pattern (its own colour-6 head and colour 8/14/9 cells).
- `ACTION1..4` move the active snake: its facing direction GROWS a head
  segment, the reverse RETRACTS the tail, a side press pushes the body.
  `ACTION6` clicks to select which snake is active (multi-snake levels);
  `ACTION7` undoes the last move.
- A fixed per-level MOVE BUDGET (196) — exhausting it LOSES (GAME_OVER).

## Mechanics Hypothesis

Shape-to-template (confirmed from the game source, dev-time only): the win
(`gvtmoopqgy`) requires every controllable snake to be shaped so the ordered
colours of the cells its body overlaps equal its template partner's colour
pattern, cell for cell. This is a configuration/arrangement condition
([[../concepts/merge_mechanic]]-adjacent), NOT a T1 "reach food" arrival —
the R57 typology's "head reaches food, +2 growth" reading is a side-effect,
not the win.

## Solution Pattern (frame-only, no clear)

Generic transition-graph exploration re-expressed through namespace-safe
kernels, with the snake body captured in the state key:
1. Mask the edge/divider HUD, then canonicalise the masked board into a
   stable state key ([[../concepts/frame_hashing]]) — the snake body IS the
   state.
2. Record every observed `(state, action, next_state)` transition (moves +
   UNDO).
3. Explore systematically: untried action at the current state, else route
   over the recorded transitions to the nearest state with an untried action.

**Why it does not clear** (R56 iteration 2, 2026-07-15 — refined via
gold-oracle replay + win-signal analysis, superseding the vague "astronomical
space" note):

- **The win IS frame-visible but SPARSE.** Each matched template segment
  lights a checkmark sprite (`kevthtkmzm`, a 2×2 block of colour `0`) in the
  BOTTOM/template half — so `count(colour-0, rows>divider) = 12 + 4·matches`
  is a clean progress read. But replaying `data/traces/sk48.npz`'s gold L0
  (13 moves, under the human baseline 61) through the live engine shows it
  stays FLAT at 0 matches for the first 8 of 13 moves, then jumps 0→1→2. No
  dense frame companion exists (top target-cell count is non-monotonic
  48→56→48; the body recolours cells, it does not deplete targets). So any
  online greedy / hill-climb / frontier search has NO gradient until ~8 moves
  from complete — depth-~8 lookahead, infeasible under the 196-move budget
  (try-then-`ACTION7`-undo costs 2 moves/probe).
- **Push is essential even for L0.** Gold L0 uses side-push on ~8 of its 13
  moves — this is not a grow-only game.

## Notes / Refactor Plan

- **Reopen (the tractable path — build-size deferred, NOT frame-blocked).**
  The state is fully frame-derivable and moves are deterministic, so the
  correct approach is a FAITHFUL OFFLINE SIMULATOR: port grow/retract/push
  (the crux is the intricate ~50-line push recursion `bnrdrdiakd` — segment
  pushing, arena-wall `qzvlbxkjgk` collision, target displacement
  `ebribtrdgw`, the `irkeobngyh` side-push gate, sliding markers), oracle-test
  it against gold's 13-move L0 win (`data/traces/sk48.npz`), then A*/IDA* over
  the simulator with the EXACT body-order template match as the goal test
  (computed internally — this sidesteps the sparse-signal wall entirely). This
  is a large, self-contained build reserved for a dedicated session; unlike
  [[G50T]] (banked because its state is NOT frame-readable), sk48 is banked
  purely on build size — it is winnable frame-only.

## Lessons Learned

- **The legacy 1/8 was budget-fragile, not robust** — raising the ensemble
  `total_budget` restored it once; the strategy also reads snake internals,
  so it never transferred. A generic frame-only explorer is honest but weak
  here because the win is a long precise shape, not a reachability target.
- The R57 typology's "T1 arrival / eat food" reading is superseded: the
  source shows a template colour-pattern match. Read the source before
  trusting a mined type.
